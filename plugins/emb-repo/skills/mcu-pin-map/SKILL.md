# 来源绑定的 MCU 引脚资料（mcu-pin-map）

把实际读取的网表整理成按外设分组、可回查来源的 MCU 引脚 Markdown，供后续 Agent 按需读取。每份产物绑定一个板卡版本和一个 MCU 位号，以及全部实际输入的路径、摘要模式与 SHA-256。脚本负责来源快照与摘要；模型负责提取、组织和标明未知项。

不要把来源未变化说成引脚表正确、原理图与网表一致或实物已验证。不要生成驱动、修改电路、执行构建或烧录。

- 生成、更新及排查校验失败前，读取 [产物格式与来源规则](references/format.md)。
- 生成正文使用 [Markdown 模板](assets/mcu-pin.md)，不要手工填写摘要。
- 工具：`python3 ${CLAUDE_SKILL_DIR}/scripts/source_binding.py`；Windows 上可用 `python` 或 `py -3` 替代 `python3`。运行要求为 Python 3.8+，不需要 PyYAML；capture 在 Git 工作树中需能运行 Git 查询 LFS 属性，check/publish 不依赖 Git。

## 输入与产出

| 项 | 说明 |
| --- | --- |
| 必需输入 | 可读取的已导出网表、明确的板卡/硬件版本/MCU 位号、项目根目录；更新和检查时还需既有引脚文档 |
| 按需输入 | 本次确实用于确认引脚名称、复用或信号含义的器件手册等仓库内文件；所有被采纳为事实依据的文件都加入来源绑定 |
| 主产物 | 一个 MCU 的引脚 Markdown；优先使用项目已有目录约定，否则建议 `docs/hardware/<board>/<revision>/<mcu-ref>-pin-map.md` |
| 检查产物 | 回复中的来源状态、逐文件的期望/实际摘要及原因；`check` 不写文件 |
| 临时文件 | 明确告知路径的输入快照目录与正文草稿；不提交进项目，也不当成新的工程索引 |

## 流程

### 1. 读取项目画像

1. **读取项目画像**：读取项目根目录 `docs/embedded-profile.md`。
   - 存在：以其中事实为准；只读取本任务需要的章节（第 2 节硬件清单、第 5 节目录约定、第 8 节文档约定，按需第 9、10 节）。若发现画像与代码不一致，以代码为准并在结尾提示用户运行 `/emb-repo:project-profile update`。
   - 不存在：按需最小化探索仓库获取本任务所需事实，并在结尾建议用户运行 `/emb-repo:project-profile` 建立画像。不要因为缺少画像而中止任务。
2. 上述“以代码为准”用于软件配置事实，不代表代码能证明硬件接线。代码与网表的引脚冲突单独报告，不用代码覆盖网表提取结果。
3. 只读画像；不要由本 skill 修改它。

### 2. 确定操作和对象

1. 将请求归为 `create`、`update` 或 `check`。只要求核查时不得转成更新。
2. 明确板卡、硬件版本、MCU 位号和目标文件。`update`/`check` 优先从既有元数据读取。多个 MCU 或硬件版本无法唯一对应时，向用户确认后再生成；不要猜型号、版本或位号。
3. 通过内容识别网表格式，不凭 `.net` 后缀猜解析方式。原生 EDA 工程、截图或无法可靠读取的格式，要求可读导出文件或使用项目已确认的导出命令；本 skill 不提供通用 EDA 转换器。
4. `create` 不覆盖既有文件。`update` 先读取旧正文、人工备注及来源列表；来源缺失不能通过悄悄删掉绑定来解决。切换板卡版本或 MCU 时创建另一份文档。

### 3. 检查分支（check）

运行以下只读命令，然后直接进入汇报：

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/source_binding.py" check \
  --root . --map "<仓库内的引脚文档路径>"
```

- `CURRENT` / 退出码 0：所有声明输入可读且摘要匹配，仅说明本次检查时来源未变化。
- `STALE` / 退出码 1：来源内容变化，列明文件和摘要差异。
- `UNVERIFIABLE` / 退出码 2：来源缺失、不可读、未展开的 Git LFS 指针或元数据不合法，列明具体原因。
- 不持久保存“当前有效”状态。后两种结果只意味着不能把该派生文档当作当前来源的准确摘要；可以直接读取原始资料继续相关工作，不阻止无关任务。

### 4. 固定生成输入（create / update）

1. 列出本次实际使用的文件，向用户说明输出及临时工作路径。来源必须是仓库内可读取的普通文件；外部资料需先由用户提供到仓库内，不能只记录网页链接并声称已绑定。
2. 在临时工作目录中指定一个尚不存在的 `snapshot` 子目录，运行：

   ```bash
   python3 "${CLAUDE_SKILL_DIR}/scripts/source_binding.py" capture \
     --root . --board "<板卡>" --revision "<硬件版本>" --mcu-ref "<MCU位号>" \
     --source "<网表的仓库相对路径>" \
     --snapshot "<临时工作目录>/snapshot"
   ```

   每个额外事实来源各加一个 `--source`。命令只写指定快照目录，不修改来源。
3. 读取快照中的 `manifest.json` 和 `sources/` 下对应副本，**根据这些副本生成正文**，不要混用稍后重新读取的活动文件。需要增加来源时，重新捕获完整输入集合。
4. 只提供网表时，明确说明仅绑定该网表，不知道它是否由当前原理图导出。另算一份原理图 SHA 不能建立导出关系。本版不自动声明原理图→网表的生成链。

完成条件：全部事实输入都在同一批快照中、对象明确、实际内容可读取；只有 LFS 指针而没有文件内容时不能继续生成。

### 5. 提取和组织正文

1. 按模板填充目标说明、来源定位、按外设分组的连接表和未知项；不复制完整网表，也不编写固件。
2. 分开记录 MCU 封装脚位、GPIO/引脚名、网名、对端位号及脚位。每条确定连接至少能通过来源路径及器件/引脚/网络重新定位。
3. 只把同一网络上的端点视为直接连接。串联电阻、跳线、收发器和电平转换器的两侧保留各自网络；需要描述信号路径时明确标注经过的器件，不能直接合并网络。
4. 网名只作为原始标识。没有手册或其他已绑定依据时，不从 `SPI2`、`RESET_N`、`ADC` 等名字确定外设实例、复用功能、有效电平、电压、地址或时序。
5. 列出目标 MCU 在输入中出现但尚未解释的脚。区分“明确 NC”“在本次导出中未出现”和“用途待确认”；网表未列出不等于未连接。不把另一个 MCU 的引脚混进目标表。
6. 明确连接资料属于资料证据 L0，不冒充 L2 实板验证；证据等级沿用 `emb-project:issue-tracking` 的 L0–L4 约定。实际飞线、贴装差异和测试结论另附来源及适用对象。
7. 人工备注放在模板的独立标记区中，不作为自动提取事实。更新时保留旧备注；来源变化后提示重新核对备注的适用性。
8. 保持速查资料紧凑：在来源说明中为文件定义短标签（如 S1），表格用标签及网络/引脚定位，不在每行重复完整路径。共同的证据边界、手册缺失和使用规则各集中说明一次；同一未知前提不拆成多行反复警告。按需合并很小的外设分组，但保留关键连接和未知项。

完成条件：来源可追溯，确定事实/推断/未知分开，没有无来源的硬件参数。

### 6. 完整写入和复核

1. 将不带 frontmatter 的正文保存为明确的临时文件。元数据由脚本从快照生成，不手填或修改 SHA。
2. 运行：

   ```bash
   python3 "${CLAUDE_SKILL_DIR}/scripts/source_binding.py" publish \
     --root . --snapshot "<临时工作目录>/snapshot" \
     --body "<临时工作目录>/body.md" --output "<目标文档的仓库相对路径>"
   ```

   只有 `update` 使用 `--replace`。脚本保留旧人工备注，检查对象一致、快照未改动及来源未变化，再一次性写入正文和绑定；失败时保留旧产物。
3. 来源在生成期间变化时，重新捕获并处理，不只替换摘要。经过重新处理而正文恰好不变是允许的。
4. 对最终文档运行第 3 步的 `check`，并人工回查关键连接。检查失败不能汇报为已交付当前资料。
5. 若项目已声明此类资料受管理，遵循 `/emb-repo:artifact-conventions` 维护现有登记入口；不因为生成了 Markdown 就强制新增登记表。登记表中的产物 SHA 与文档内的输入 SHA 分属两种检查，不能互相替代。

### 7. 交接给消费者

建议通过 `/emb-repo:project-profile update` 在第 2 节加入文档链接，不复制长表。需要让普通编码任务默认使用时，提出由项目现有维护流程加入下面的规则；未经授权不改 `AGENTS.md`、`CLAUDE.md` 或画像：

> 使用引脚资料前确认板卡/版本/MCU 位号，并运行来源检查；通过后仅读取相关外设章节。来源变化或无法核验时，重新生成资料或直接读取当前来源，不依据旧表确定新代码中的引脚配置。未知项仍需查证。

安装 skill 或存在元数据本身不保证其他 Agent 自动执行该规则。本版不新增 hook、全仓库扫描或强制 CI 门禁。

## 自检

- [ ] 操作与授权一致，`check` 没有写文件；不同板卡版本或 MCU 没有互相覆盖。
- [ ] 事实来自本批快照，全部实际来源均绑定；未虚构原理图导出链。
- [ ] 物理脚位、引脚名、网名及对端分开，确定结论可回查；未知项没有被猜测填满。
- [ ] 正文和来源绑定成组写入，最终来源检查已运行；更新保留人工备注。
- [ ] 未把来源匹配当成内容正确、已批准或实板验证，也未增加无关项目门禁。

## 汇报

按“操作与结果 → 目标文档及适用对象 → 输入文件与来源检查结果 → 待确认项 → 必要的下一步”汇报。说明只依据网表时的导出链限制；失败时说清保留了什么、缺什么。不要把临时快照列为正式交付物。

## 约束

- 不提供“只刷新 SHA”操作，不改原始网表或手册，不用源代码证明接线正确。
- 不承诺所有 EDA 格式可解析，不推断原理图与网表对应，不替用户执行未知的导出命令。
- 不修改项目画像、设备状态、密钥、Git 历史或远端；需要这些动作时交给原有流程并取得相应授权。
- 来源绑定是可核验的依赖记录，不是签名、防恶意篡改机制或硬件正确性证明。
