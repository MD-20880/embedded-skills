# 项目画像规范（Project Profile Spec）

> 版本：1。本文件是项目画像的**唯一权威定义**。所有插件中需要项目事实的 skill 都按本规范读取画像；修改本规范须同步升级 `emb-repo` 的版本并在 CHANGELOG 中说明。

## 1. 它解决什么问题

嵌入式 skill 的方法是通用的，但每个项目的事实不同：用哪颗 MCU、怎么构建和烧录、驱动放在哪个目录、用不用 RTOS。
如果每个 skill 每次都重新探索仓库，结果既慢又不稳定。项目画像把这些事实**一次整理、带来源、可复核**地写进项目仓库，供所有 skill 共用。

## 2. 位置与格式

| 项 | 约定 |
| --- | --- |
| 路径 | 项目根目录下 `docs/embedded-profile.md`（随项目代码一起提交；它同时是新成员了解项目的速览） |
| 为什么不放 `.claude/` | `.claude/` 是 Claude Code 的受保护目录，写入总需人工确认，非交互和自动化场景会被拒绝 |
| 格式 | Markdown，首部 YAML frontmatter 放机器可读的元数据，正文按第 4 节的固定章节组织 |
| 语言 | 与项目文档语言一致；章节标题保持本规范中的中文标题，便于 skill 定位 |
| 篇幅 | 建议 ≤ 200 行。细节写在项目自己的文档里，画像只给结论和链接 |

## 3. Frontmatter

```yaml
---
profile_version: 1            # 本规范的版本号，必填
project: overide-glove        # 项目标识，必填
updated: 2026-10-06           # 最后核对日期，必填
generated_by: emb-repo:project-profile   # 生成或最后更新它的 skill，可选
---
```

## 4. 正文章节

章节**顺序和标题固定**；某章节不适用时保留标题，写“不适用”及原因。每条事实都要带来源（文件路径或“用户确认”），没有证据的内容放到第 10 节“待确认”。

| # | 章节标题 | 必须回答的问题 | 典型消费者 |
| --- | --- | --- | --- |
| 1 | 项目概述 | 产品是什么、仓库包含什么、当前阶段（原型 / 调试 / 量产） | 全部 |
| 2 | 硬件清单 | 每块板：名称与版本、MCU 型号、内核、主频、Flash/RAM、关键外设芯片；原理图与芯片手册位置 | drivers、bringup、design |
| 3 | 软件栈 | RTOS / 裸机、厂商 SDK / HAL 及版本、第三方库、语言标准 | drivers、review |
| 4 | 构建与烧录 | 构建系统、工具链及版本、构建命令（逐板）、烧录与调试命令、调试器 | bringup、repo |
| 5 | 目录约定 | 各顶层目录的职责；新增板子 / 驱动 / 程序 / 文档应放在哪里 | 全部 |
| 6 | 编码约定 | 命名、错误处理、日志、内存分配策略、中断与并发规则、格式化 / 静态检查工具 | drivers、review |
| 7 | 测试与验证 | 主机测试怎么跑、上板验证程序在哪、验证记录写在哪、什么算“验证完成” | bringup、review |
| 8 | 文档约定 | 文档索引入口、协议 / 设计文档放在哪、模板与写作要求 | docs、design |
| 9 | 已知约束与坑 | 硬件缺陷、勘误、时序限制、资源紧张点、历史踩坑结论 | 全部 |
| 10 | 待确认 | 扫描无法确定、需要人确认的问题清单 | 维护者 |

## 5. 事实条目写法

- 一条事实一行，结尾用括号标注来源：`MCU：GD32F303RCT6，Cortex-M4 @120 MHz（boards/a2_bottom_v1/README.md）`。
- 来源只能是：仓库内相对路径、命令输出（写出命令）、或 `用户确认 YYYY-MM-DD`。
- 能链接就不复制：长表格、引脚表、寄存器表一律链接到项目文档。
- 多板项目在第 2、4 节用表格，一行一块板。

## 6. Skill 如何消费画像（写给 skill 作者）

在需要项目事实的 skill 的流程第一步写入如下约定（可直接复制）：

```markdown
1. **读取项目画像**：读取项目根目录 `docs/embedded-profile.md`。
   - 存在：以其中事实为准；只读取本任务需要的章节。若发现画像与代码不一致，以代码为准并在结尾提示用户运行 `/emb-repo:project-profile update`。
   - 不存在：按需最小化探索仓库获取本任务所需事实，并在结尾建议用户运行 `/emb-repo:project-profile` 建立画像。不要因为缺少画像而中止任务。
```

消费规则：

1. **只读不写**：除 `emb-repo:project-profile` 外，任何 skill 都不修改画像。
2. **按章节取用**：通过章节标题定位，只读取本任务需要的章节。
3. **冲突以代码为准**：画像是缓存，仓库是事实源。
4. **待确认项不当事实用**：第 10 节中的内容需要向用户确认后才能作为依据。

## 7. 维护策略

| 时机 | 动作 |
| --- | --- |
| 项目首次接入本仓库的 skills | `/emb-repo:project-profile`（init） |
| 新增板子 / 硬件改版 / 换构建方式 | `/emb-repo:project-profile update` |
| 定期或发版前 | `/emb-repo:project-profile check`，只报告过期项，不改文件 |

## 8. 版本演进

- 新增可选内容：不升 `profile_version`。
- 新增 / 重命名 / 删除章节：`profile_version` 加 1；`project-profile` skill 需能把旧版本画像迁移到新版本（update 模式负责）。
