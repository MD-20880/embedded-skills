# 文档分类和权威性判定

## 先问它回答什么，再问它放哪里

| 类型 | 要回答的问题 | 常见管理方式 | 权威性来源 |
| --- | --- | --- | --- |
| 外部约束：法规、标准、Datasheet、原理图、BOM | 哪些客观条件约束我们？ | 保留原件、修订版、来源链接、SHA-256，明确适用料号/板卡版次 | 供应商正式资料、适用版本与经核验的实物 |
| 内部需求 | 产品为什么需要这种能力？ | 需求系统中的稳定 ID、适用产品/版本、验收目标 | 需求所有者批准的版本 |
| 系统方案 | 关键职责和资源为何这样划分？ | 版本化方案，可仍在评审 | 文档自身审批状态；需要解释的取舍由 ADR 关联 |
| 协议/工程契约 | 各端必须保证哪些字段、状态、时限及异常行为？ | 稳定文档 ID、版本与关键条款、兼容性策略 | 正式接受的协议修订；RC 仅是候选，除非范围被明确批准 |
| 实现方案 | 在当前契约下怎样组织软硬件实现？ | 可随测试迭代，标依赖协议版本 | 实际实现及经过评审的方案基线 |
| ADR | 当时为何接受一种非显然选择并拒绝其他选择？ | Nygard 格式、Proposed/Accepted/Superseded，保留完整历史 | 决策者明确确认；ADR 不是精确线格式定义源 |
| Issue/问题 | 现象、探索、阻塞、待定结论及谁负责？ | 使用项目现有工单与标签，不另造重复任务表 | 经证据支持的当前问题状态；关闭与否不证明产品已验收 |
| 验证计划 | 什么对象、工况、指标才算通过？ | 明确硬件版本、固件配置、判据、方法和证据等级 | 已批准的验收定义 |
| 原始验证记录/证据 | 什么条件下测到了什么？ | 结果、时间、版本、原始波形/日志，不覆写旧记录 | 可复核的原始证据，未必可推广到其他硬件 |
| 历史/实验/旧 Demo | 过去曾如何实现或测试？ | 标为 Historical/Experimental/Validation Only，给当前入口链接 | 仅对当时的版本、环境有效 |
| 模块使用说明 | 当前模块如何使用、编译、诊断？ | 紧邻所属模块的 README、源码 API 注释 | 与当前代码版本匹配 |
| 索引/入口 | 谁是当前有效文档？从哪里开始读？ | 简短导航，不复制协议正文 | 源文件状态，索引本身不重新定义行为 |

## 推荐的概念分区（不是强制迁移）

可映射到仓库现有路径，不要求名字完全相同：

- `docs/README.md`：权威入口和文档分类索引，标注当前/候选/历史。
- `docs/requirements/` 或外部需求系统：产品要求与批准状态。
- `docs/specs/` 或现有协议目录：产品接口和行为契约。
- `docs/design/`：系统方案、实施设计、资源预算。
- `docs/adr/`：重要取舍的历史决定。
- `docs/references/` 或现有 `datasheets/`、`hardware/`：原始外部证据及索引。
- `docs/verification/`：验收计划和当前判据；实际脚本留在测试目录。
- `docs/records/`：不可改写的测试原始记录；`docs/history/`：过期方案、旧 Demo 的历史入口。
- 模块目录 README：如何使用当前代码和诊断模块；Issue 仍由工单系统管理。

**不要把“方案、协议、ADR、验证”全部放在 `docs/` 根目录并依赖文件名猜权威性。** 但若当前目录已有稳定引用，优先通过索引/元数据划分逻辑分类，只有在收益明确、断链可控时才物理移动。

## 文档头部最小元数据

- 文档标识与版本（或外部来源/修订/哈希）。
- 类型：依据/需求/方案/协议/ADR/验证/记录/历史/入口。
- 状态：真实的项目审批状态；不要统一强行替换已有状态词。
- 适用对象：产品、硬件版本、固件及协议版本范围。
- 权威/上游依据：链接到当前正式定义。
- 实现和验证入口：有则链接，无则标未实现/未验证。
- 维护负责人或决策人：未知写待确认。

原始实验记录不必事后加完整新格式；可由外部索引补元数据，避免篡改历史。

## 冲突判别

1. 两份文件对同一功能给出不同规则：先核对状态、版本与作用范围，不能默认“最后修改者胜”。
2. 旧 Demo 文档看起来比正式规范更详细：旧文档是历史实现证据，不代表目标产品协议。
3. 通过脚本验证字段布局：只能证明该脚本覆盖的模型/向量；不能宣称实板或现场合规。
4. Accepted ADR 与新方案冲突：新方案先作为提案；正式取代遵守 ADR 工具和人类确认流程。
5. 外部 PDF 更新：复核与实际器件/板卡适配，不能直接将新版手册要求强套旧硬件。
