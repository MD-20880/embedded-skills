# 工程知识与文档治理约定（项目模板）

> 使用说明：只在用户要求将治理规则落地到具体项目时复制、删减并填入项目事实。目录不必与模板相同，不将模板全文照搬到已经有清晰规则的项目。

## 3. 变更和决策边界

- Issue：问题、假设、待裁决与推进状态，不代替正式规范。
- 协议/方案：当前要求遵守的行为和分工，变更需声明适用版本及消费者。
- ADR：重大非显然取舍的理由，先 Proposed，正式确认后 Accepted，变更用 Supersedes/Amends。
- 代码/构建/验证：从工程依据推导职责，但以实际产物/测量确认是否符合。

## 5. 交接与诊断入口

每个当前交付主题应能定位：适用版本、协议约束、代码/Target 所有者、测试或实板记录、已知限制、未解决问题。历史讨论供追溯，但不是阅读当前系统的前提。
